omniagentos/scheduler/loop_receipts_admin.py:main  Operator-invoked entry point, and the only public symbol in the module: `python -m omniagentos.scheduler.loop_receipts_admin [--db PATH] list|show|release`, an admin CLI for releasing a loop idempotency receipt wedged on an UNKNOWN outcome. Its caller is a human at a terminal, deliberately not the scheduler, and an automatic caller would BE the defect rather than the fix: releasing a claim re-licenses a paid call, and an UNKNOWN receipt is precisely the case where nothing observable says whether the provider already charged — so a timer, janitor or reconciler brings no new evidence to the decision and would merely convert every UNKNOWN into an assumed ABSENCE, which is the double-billing bug this lane exists to close. The evidence lives outside this process (the provider's dashboard) and cannot be manufactured inside it, so the release function requires a `_ProviderChecked` value naming the human and what they saw, and cannot be called without one. Read this entry sceptically on one point, in the spirit of the JG3-BE block above: `main` would pass the gate anyway, because the gate matches BARE SYMBOL NAMES and 96 files under `omniagentos/` and `scripts/` — precisely the paths it searches for callers — define `def main(` — so this line is the recorded decision, not the thing suppressing a refusal. It replaces an earlier entry naming `claimed_receipts`, which was the wrong symbol: that is an internal read helper (now `_claimed_receipts`) and never was an entry point, and recording it as one hid the fact that the module's genuinely destructive function, `release_claim`, was public, unwired, and reading as wired only because unrelated `release_claim` methods exist on `CollabStore` and the gate-evidence store. Verified invokable end-to-end against the live DB (`--db var/runtime/state.sqlite3 list` -> "no claimed-and-uncompleted loop receipts", rc=0).
