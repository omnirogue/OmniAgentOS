# Relay CLI invocation matrix (fragment)

Authoritative per-CLI invocation facts for relay/orchestrator sessions. Every fact
here was PAID FOR by a measured failure — do not improvise alternatives.

## codex (GPT-5.6 Sol/Terra/Luna)
- `codex exec --model <m> -c model_reasoning_effort=<tier> --sandbox read-only -C <repo> "<prompt>" < /dev/null`
  — ALWAYS close stdin (`< /dev/null`) or exec hangs on "Reading additional input from stdin".
- `codex exec resume <sid> "<prompt>"` — takes only `--model` before the sid; MUST run from a
  trusted directory (the repo), else "Not inside a trusted directory" (or pass --skip-git-repo-check).
- p90 turn is ~14 min: run_in_background + notification, or ONE ≥600s blocking wait. Never poll.
- Weekly-window preflight before fan-out: newest rollout's token_count rate_limits.used_percent < 85.
- Relay verification is MANDATORY: demand a nonce echo + model attestation (exact model string +
  session id from the rollout); a missing/wrong nonce = relay_failed, never a usable review.
  Pass the brief INLINE in argv — never via a shared file like .fusion/REVIEW.md (stale-brief class).

## kimi (K3)
- `kimi -p "<prompt>"` — prompt mode CANNOT combine with --yolo or --auto (both error).
- Continue a session: `kimi -c -p "..."` (cwd-keyed) or `kimi -S <id> -p "..."`.
- No stdin/file prompt transport: argv only; keep < 700KB.
- Kimi can finish but fail to DELIVER text: recover from ~/.kimi-code/sessions/*/wire.jsonl
  (finishReason=end_turn proves completion).

## claude (headless)
- `claude -p --model <m> --system-prompt "<text>" --max-turns N "<task>"`.
- Effort rides the invoking profile's settings.json; there is no per-call effort flag.

## gemini / grok
- Never foreground in Bash; background + notification, same as codex.
